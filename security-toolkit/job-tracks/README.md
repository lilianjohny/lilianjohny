# Job-Targeted Tracks

Each file here maps a **specific job posting** to concrete evidence in this
portfolio: which requirement is covered by which tool, lab, or section — and,
where something was missing, the tool/lab that was **built to close the gap**.

Use these as interview prep and as a résumé-to-evidence index: for any bullet in
the job description, you can point to something you built and can run.

| Track | Role | Emphasis |
|-------|------|----------|

| [`openai-infrasec.md`](openai-infrasec.md) | OpenAI — Security Engineer, Infrastructure Security | Multi-cloud + on-prem/datacenter, K8s, service mesh, secret mgmt, machine identity |
| [`jobgether-cybersecurity-engineer.md`](jobgether-cybersecurity-engineer.md) | Cybersecurity Engineer (SOC / IR) | Incident response, SOC alert triage, firewall/EDR, M365/Entra + Graph, ticketing |

## How each track is organized
1. **Requirement → evidence matrix** — every JD line → tool/lab/section, marked
   ✅ covered / 🆕 built-to-close-gap / 📁 reference.
2. **Tools built for this job** — the new CLI tools, with run commands.
3. **Labs to do** — the hands-on labs that produce portfolio artifacts.
4. **Certs & study pointers** — what the posting asks for.
5. **Interview talking points** — how to tell the story.

> New CLI tools live in their natural home in the toolkit (e.g. `cloud/aws/`,
> `cloud/dr/`, `compliance/stig/`, `soc/…`) so they're reusable across jobs —
> the tracks just point to them.
